# LoraDB Docs

Documentation site for **LoraDB** — an in-memory graph database with a
Cypher-like query engine, written in Rust.

Built with [Docusaurus](https://docusaurus.io/) v3.

## Develop

Run these commands from the repository root:

```bash
corepack enable
corepack yarn install --immutable
corepack yarn workspace @loradb/lora-query build
corepack yarn workspace loradb-docs start
```

The dev server runs at <http://localhost:3000/docs/>.

## Build

```bash
corepack yarn workspace @loradb/lora-query build
corepack yarn workspace loradb-docs validate-cypher
corepack yarn workspace loradb-docs build
corepack yarn workspace loradb-docs serve   # preview the production build
```

The production build also emits crawler-facing generated files:

- `sitemap.xml` — generated by Docusaurus with per-route priority tiers.
- `llms.txt` — a curated index for AI clients and answer engines.
- `llms-full.txt` — one-file Markdown bundle for the same curated pages.

After a production deploy, submit updated URLs to IndexNow when needed:

```bash
corepack yarn workspace loradb-docs indexnow --dry-run
corepack yarn workspace loradb-docs indexnow --since=24h
```

The site extends the classic Docusaurus theme and the Ionic design-system
tokens package (`@ionic-internal/ionic-ds`) for its color palette; the Ionic
_content_, plugins, and framework-specific pages have been removed.

## Editing docs

For detailed writing conventions, see
[`CONTRIBUTING-DOCS.md`](./CONTRIBUTING-DOCS.md). The short version:

- Put user-facing product and query documentation in `apps/loradb.com/docs/`.
- Put engine internals, ADRs, and contributor-only material in the
  repository-level [`../../docs`](../../docs) tree.
- Prefer runnable `QueryCodeBlock` examples for Cypher that a reader
  should be able to paste into the playground. Use `CypherSnippet`
  for syntax fragments, intentionally invalid examples, or reference
  shapes that are not full queries.
- Run `corepack yarn workspace loradb-docs validate-cypher` before
  shipping query-doc changes; it should report `invalid: 0`.
- When a page needs existing data, include the seed query or link to the
  exact setup step.
- Call out persistence explicitly: in-memory handles start empty after
  process restart; snapshots, named `.loradb` archives, and WAL-backed opens
  are opt-in.
- When a runtime capability changes, update the matching quickstart,
  [`docs/limitations.md`](./docs/limitations.md),
  [`docs/troubleshooting.md`](./docs/troubleshooting.md), and any
  reference page that mentions the old boundary.

## Deployment

The site is deployed to **Cloudflare Pages** at <https://loradb.com> by the
[`loradb-docs`](../../.github/workflows/loradb-docs.yml) GitHub Actions
workflow.

Deploy policy:

- Pull requests that touch `apps/loradb.com/**`, `packages/lora-query/**`, or
  the workflow build the site and upload the build output as an inspection
  artifact. They do not deploy.
- Tag pushes matching `vX.Y.Z[-pre]`, `release.released`, and manual
  `workflow_dispatch` runs deploy `apps/loradb.com/build` to the Cloudflare
  Pages project `loradb-docs`.
- Pushes to `main` do not publish docs automatically. For a docs-only
  production update, cut a patch tag or run the workflow manually.

### Cloudflare setup (one-time)

1. In Cloudflare, create a Pages project named `loradb-docs` using **Direct
   Upload**. Do not connect a Git source; GitHub Actions owns the build and
   deploy path.
2. Attach `loradb.com` as the custom domain in the Pages project and follow
   the DNS instructions Cloudflare provides for the zone.
3. In GitHub repository secrets, add:
   - `CLOUDFLARE_API_TOKEN` — token scoped to **Cloudflare Pages: Edit**.
   - `CLOUDFLARE_ACCOUNT_ID` — visible in the Cloudflare dashboard sidebar.
4. Keep the GitHub environment named `production` restricted to trusted refs.
   The workflow targets that environment for deploys.

### SEO and crawler artifacts

The build verifies that `robots.txt` and `sitemap.xml` exist. Additional
crawler artifacts are generated or copied during the Docusaurus build:

- `static/robots.txt` is copied to `/robots.txt`.
- `@docusaurus/plugin-sitemap` emits `/sitemap.xml`.
- `plugins/llms-txt` emits `/llms.txt` and `/llms-full.txt`.
- `plugins/noindex` rewrites thin generated pages after build so tag,
  author, pagination, and local-search routes stay out of search indexes.
- `static/<INDEXNOW_KEY>.txt` is copied for IndexNow ownership verification.
  After a deploy, `corepack yarn workspace loradb-docs indexnow --dry-run`
  shows which URLs would be submitted.

### Local development

Local development is unaffected by the production Pages configuration —
`corepack yarn workspace loradb-docs start` still serves at
`http://localhost:3000/` independent of `url` / `baseUrl`.
